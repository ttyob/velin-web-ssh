# 内置 Telegram Bot

## 目标

手机通过 Telegram 查看既有 SSH/tmux 会话、补充开发需求、接收关键变化通知和传递文件。完整终端通过工作台链接打开。基础能力不依赖 AI，不限制远端开发任务运行时长。

## 配置与使用

1. 在 Telegram 的 `@BotFather` 创建专用 Bot，获取 Bot Token。
2. 管理员打开工作台 **设置 → Telegram → 机器人配置**，填写 Token、手机可访问的工作台地址，按需填写 Telegram 代理。点击“测试连接”，启用后保存。
3. 在“会话授权”选择允许访问的会话或 SSH 主机，勾选需要的输入、创建/恢复、管理、文件传输权限并保存。选择主机也会授权该主机今后创建的会话。
4. 生成绑定链接，用手机打开或扫描二维码，在 Telegram 中点击启动。链接 10 分钟有效，使用一次后失效；重新生成会使旧链接失效。
5. 向 Bot 发送 `/sessions`，选择会话。回复卡片发送需求，点击“开启通知”订阅该会话。未回复卡片的消息会先要求选择目标。

代理地址从 **Velin 服务进程** 所在网络访问；Docker 中的 `127.0.0.1` 指容器自身。支持 HTTP、HTTPS、SOCKS5/SOCKS5H，包括带账号密码的地址。此设置仅用于 Telegram，不读取环境代理或 AI 模型代理。已保存的 Token、代理地址不会在面板回显；Token 留空保持原值，代理可通过“移除已保存代理”清除。

会话卡片提供刷新进度、更多输出、常用按键和打开终端。授权后可创建/恢复 tmux、重命名、终止会话；中断和终止均需确认。点击“打开终端”后若需要登录或首次修改密码，会保留目标会话；最终仍按浏览器当前账号校验访问权限。

回复卡片上传图片或文档，会保存到 **当前 tmux 项目目录的 `clipboard/`**。图片说明会保留，点击“粘贴说明和路径”可送入输入区，不自动发送回车；没有说明时只粘贴路径。下载在“更多操作 → 下载项目文件”中输入相对路径，例如 `logs/build.log`。上传文件不会自动清理，请在项目中按需删除。

通知按会话独立开启、关闭，最多订阅 20 个会话。每 10 秒观察连接与输出变化，原进度卡片最多每 30 秒更新一次；只有订阅后实际产生新输出，再持续无输出，才触发静默提醒。可以在 Telegram 卡片或网页设置中关闭通知；解除绑定会同时撤销会话授权和订阅。

## 当前限制

- 一个服务配置一个 Bot，每个 Velin 用户绑定一个 Telegram 私聊账号。群聊、频道、语音暂不支持。
- 同一个 Bot Token 只在一个实例启用。使用长轮询，不开放 webhook；检测到已有 webhook 会要求改用独立 Bot 或由管理员处理原 webhook。
- 文件需要已连接 tmux 和明确的项目目录，单个文件最多 20 MiB。下载不跟随符号链接，不允许目录打包或项目外路径。
- 服务重启后，tmux 远端任务可继续运行，但需先恢复 Velin 的 SSH 连接，才能继续读取输出、观察变化或传输文件。
- Bot 只等待单次操作响应，不等待 CLI 开发任务结束；远端任务可以持续运行数小时。响应超时或执行结果不确定时，先查看状态，再决定是否重新发送。
- 已接收的更新在执行前记录，避免重启后重复输入。若处理途中服务退出，该条消息不会自动补发，请查看终端后再决定下一步。
- 不生成 AI 摘要，不推断“任务完成”或“等待批准”。精确通知需后续增加对应 CLI 事件接入。

## 交互与边界

一个服务配置一个 Bot，使用 getUpdates 长轮询，无需 Telegram 回调入口。只接受已绑定的私聊数字用户 ID。每个 Velin 用户单独选择范围，复用外部 Agent 的授权校验；读取、输入、管理和文件传输分别控制。Bot Token 不进入日志或普通用户响应。禁用机器人、解绑、停用用户或撤销令牌后停止后续操作。

会话标题和主机始终显示；回复哪张卡片就操作哪个会话，不依赖全局“当前会话”。普通消息没有目标时先选择。按钮需要重新检查权限，带内容的临时操作限时、加密保存。输入回执只证明终端接收，不证明任务完成；不确定的输入不自动重发。

通知只描述可观察事实：连接变化、有新输出、持续无新输出。静默不等于完成。第一版不通过通用文字匹配生成“开发完成/待批准”的确定性通知；这些需要将来的 CLI 事件适配。读取不会接管、缩放或滚动现有终端。

文件单个最多 20 MiB，通过网络流传递，不在服务端持久化文件副本。上传使用独立随机文件名，不覆盖既有文件；路径明确展示。文件能力要求单独授权和已连接 tmux，目录无法确定时拒绝上传。下载仅允许当前项目目录内的普通文件，检查规范路径和链接边界。文件由项目持有，不自动删除远端资料。

## 模块位置

- `internal/telegram/`：Bot API 客户端、配置、绑定、路由、卡片、通知及附加表。
- `internal/api/telegram.go`：认证后的配置接口与现有会话/文件能力适配。
- `web/src/features/telegram/`：设置面板。
- `internal/sessionbridge/native.go`：受相同权限保护的进程内会话调用。
- 其余接入点：API 初始化/关闭、服务退出、设置菜单、工作台会话深链接。

## 验收记录

自动测试使用本地 Bot API 模拟端、临时数据库与真实 SFTP 协议测试通道，不向真实聊天发送消息，不修改已部署服务的数据。

- 后端：绑定过期/一次性消费、跨用户/Bot 隔离、加密存储、授权撤销、回复路由、重复消息与回执、轮询重启、通知去重/卡片节流、上传/下载权限和文件边界。
- 前端：机器人测试/保存、代理保持、授权校验、CSRF、绑定链接、解绑、订阅、普通用户权限、窄屏无溢出；登录/首次改密码后保留会话链接并打开目标。
- 检查命令：`go test ./...`、`go vet ./...`、相关模块 `go test -race`、`npm --prefix web test`、`test:telegram`、`test:auth`、`npm --prefix web run build`，以及 Windows 桌面构建交叉检查。

真实 Telegram 联调需要管理员填写自己的 Bot Token，并在 Telegram 中主动完成绑定；此次没有启用真实 Bot。

## 整块移除

先在设置中停用 Bot。移除 `internal/telegram/`、`internal/api/telegram*.go`、前端 `features/telegram/`、对应浏览器测试，以及 API、服务生命周期和设置菜单中的接入点。工作台会话链接和 `sessionbridge/native.go` 是通用能力，可以保留；如一并删除，需撤回对应 router、登录/改密码和工作台接入。

数据库表为附加表。清理时先记录 `telegram_bindings.token_id`，删除 `telegram_routes`、`telegram_actions`、`telegram_subscriptions`，再删除 `telegram_bindings`、`telegram_runtime`，最后只删除刚才记录的 Telegram 内部授权令牌和 `system_settings` 中的 `telegram_bot` 配置。保留用户其他外部 Agent 的令牌、主机和终端会话。无需修改现有主机或终端表结构。
